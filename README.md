## 2. 지금 바로 써 보기 (서버 없이, 이 기기에서만)

1. `app/index.html`을 Chrome이나 Edge로 엽니다 (더블클릭).
2. **서버 없이 이 기기에서만 쓰기**를 누릅니다.
3. **문제은행 파일 열기** → `private/pilgi-2026-1.json`을 고릅니다.
4. 홈에서 **회차 시작**을 누르면 2026년 1회 100문항이 열립니다.

이 모드의 기록은 그 브라우저에만 남습니다. 나중에 계정 모드로 옮길 때는 설정 → 백업 내려받기 → (로그인 후) 백업 불러오기를 쓰면 됩니다.

## 3. PC↔휴대폰 연동 켜기 (진영님 승인 후 진행)

기존 v6 사이트와 서버 기록은 지우지 않습니다. 새 버전은 별도 주소(`/v7/`)와 새 표(`kgs_` 로 시작)를 씁니다.

1. **백업**: Supabase 대시보드 → Database → Backups 확인. v6 쓰던 기기에서 JSON 백업도 받아 둡니다.
2. **현재 상태 확인**: SQL Editor에 `server/002_check_readonly.sql`을 붙여 실행하고 결과를 Claude에게 보여 줍니다. (읽기만 함)
3. **표 만들기**: SQL Editor에서 `server/001_kgs_schema.sql` 실행.
4. **문제은행 올리기**: Storage → `kgs-bank` 보관함(비공개) → `private/pilgi-2026-1.json`을 이름 그대로 업로드.
5. **주소·키 넣기**: `app/config.js`에 Project URL과 **publishable(anon) 키**를 넣습니다. (service_role·secret 키는 절대 넣지 않음)
6. **배포**: GitHub 저장소에 `v7/` 폴더를 만들고 `app/`의 파일 5개만 올립니다. → `https://chlwjdgns302-beep.github.io/study-dashboard/v7/`
7. **Auth 설정**: Authentication → URL Configuration에 위 v7 주소를 Redirect URL로 추가합니다.
8. **계정**: 남편 계정과 진영님 계정을 앱에서 가입(메일 확인)한 뒤, `001` 파일 맨 아래 예시 SQL로 남편=learner, 진영님=editor를 등록합니다. 다 만든 뒤에는 Authentication 설정에서 새 가입을 꺼 두는 것을 권합니다.
9. **서버 접근 점검**: 진영님 계정으로 로그인 → 설정 → **서버 접근 점검**. 등록하지 않은 점검용 계정(B)을 하나 만들어 넣으면, 다른 계정·비로그인이 남편 기록과 문제은행에 접근하지 못하는지 15가지를 확인합니다. 모두 ✔ 여야 합니다.

## 4. PC와 휴대폰으로 직접 확인하는 순서 (인수 테스트 1~6)

| 순서 | 할 일 | 맞는 결과 |
|---|---|---|
| 1 | PC에서 남편 계정 로그인 → 회차 시작 → 1~7번 제출 → 8번 화면에서 멈춤 | 오른쪽 위 **서버 저장 완료** |
| 2 | 휴대폰에서 같은 계정 로그인 | 홈에 **8번부터 이어서 풀기**, 과목 표 숫자가 PC와 같음 |
| 3 | 휴대폰에서 8번 제출 → 다음 | PC에서 오른쪽 위 배지를 누르면 **9번부터 이어서 풀기**, 기록 화면에 8번 |
| 4 | 휴대폰 비행기 모드 → 9번 제출 → 앱 닫기 → 다시 열기 | 답이 남아 있고 **이 기기에 저장됨 · 전송 대기** |
| 5 | 비행기 모드 끄기 | 잠시 후 **서버 저장 완료**. `002` 점검 SQL의 7번 결과에서 제출 수가 1만 늘어남 |
| 6 | PC·휴대폰 모두 인터넷 끊고 각각 다른 문제 풀기 → 연결 | 두 기기 모두에 두 기록이 다 보임 |
| 7 | 문제 풀기 → 오답·헷갈림 복습 → 1문제 풀기 | 과목 표의 **재풀이**만 1 늘고 첫 풀이 정답률은 그대로 |
| 8 | 로그아웃 → 다른 계정 로그인 | 남편 기록·문제은행이 보이지 않음 |

## 6. 문제은행 연결 결과

- 문제집 PDF 4~31쪽 ↔ 해설집 분할본 1의 4~51쪽, 100문항 모두 연결.
- 정답은 해설집에서 초록 원으로 표시된 번호를 읽었습니다. 100문항 모두 정답 표시가 정확히 1개씩 확인됐습니다.
- **대조 완료 99문항, 검토 대기 1문항(56번)**: 56번은 정답(①)이 읽혔지만, 아래첨자 표기 때문에 문제집·해설집 문장 일치도가 기준(0.85)보다 낮은 0.82가 나왔습니다. 앱의 설정 → 정답 대조에서 두 원문을 나란히 보고 확정하면 됩니다.
- 52·55·73번은 위첨자·수식이 글자로 깨질 수 있어 문제 화면에 원문 이미지를 함께 보여 줍니다. 그림이 있는 12문항(그림 12개)은 원문에서 잘라 넣었습니다.
- 해설은 수식이 글자로 깨져서 해설집 원문을 이미지로 잘라 보여 줍니다.
- 과목은 보내 주신 출제기준(적용 2025.01.01~2029.12.31: 계획·시공·구조·설비·법규 각 20문항)의 순서대로 번호 구간에 맞춰 나눴습니다.

## 7. 개발자용

```sh
node tests/run-tests.cjs                 # 논리·모의 동기화 (16)
node tests/e2e/run-e2e.cjs               # 헤드리스 Chrome + 모의 서버 (10), 화면 사진은 tests/e2e/shots/
PGHOST=... sh tests/sql/run-sql-test.sh  # PostgreSQL 16에서 서버 SQL·RLS (21)
# 다른 회차 추가: tools/extract_bank.py(문제집) → tools/link_answers.py(해설집)
```

- 기록 저장 방식: 제출·회차 시작·현재 문항을 '사건' 한 줄씩 쌓고(수정·삭제 없음), 통계는 매번 같은 계산식으로 다시 셉니다. 그래서 PC와 휴대폰 숫자가 같고, 한 기기 기록이 다른 기기 기록을 덮어쓰지 않습니다.
- 제출마다 기기에서 만든 고유 ID가 붙고, 서버는 같은 ID를 두 번 받아도 한 번만 저장합니다.
- 기존 v6 코드(`cloud-ui.js` 등)는 이번에 받지 못해 재사용하지 않았습니다. v6 표·기록은 그대로 둡니다.

## 8. 역할

| 역할 | 할 수 있는 것 |
|---|---|
| learner (남편) | 문제 풀기, 자기 기록 보기 |
| admin (진영) | 학습자 기록 **읽기 전용** 보기(메뉴 '학습자 기록'), 정답 대조, 서버 접근 점검, 자기 풀이 |
| editor | 정답 대조, 서버 접근 점검 (학습자 기록은 못 봄) |

어느 역할도 다른 사람의 기록을 고치거나 지울 수 없습니다. 미등록 계정은 문제은행과 어떤 기록도 볼 수 없습니다.
